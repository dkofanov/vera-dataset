# VERA stdlib illustrations — DeepSeek-authored augmentation

This is a lightweight **illustrative augmentation tier**, separate from the
source-backed chapters. DeepSeek generated concise natural-language tasks and
VERA implementations for reviewed VERA-native seed contracts. These are not newly
harvested applications, upstream translations, or independent task discoveries.

## First batch

- Teacher: `https://api.deepseek.com/chat/completions`, `deepseek-flash`, thinking
  disabled; temperature 0.7; 40 requests, three variants per request.
- 40 selected **old joint-training seed tasks**, 120 candidate variants.
- **111 accepted variants**, representing **38 parent tasks / 29 family labels**.
  **Zero new independent tasks.** Names, wording, and parameter positions vary.
- **11,338 passing compiler/VM behavior cases**. Each variant replays the parent's
  persisted inputs plus 32 fresh deterministic inputs from its reviewed generator.
- **35 directional argument-swap witnesses**, reference-replayed. These are explicit
  nonempty/asymmetric examples showing why search/replacement roles matter.
- 9 quarantined variants in `rejected.json`: three compiler/API failures for field
  counting, three parser-contract/API failures, and three prompt ambiguities.
- 49,581 teacher tokens reported: 34,785 input + 14,796 output. No monetary cost
  estimate is claimed.

All variants are training-only. They inherit old joint-training groups; old joint
holdout alpha clones reject, and alpha-connected new candidates are grouped.
Parent group links are retained as `parentGroup`: a future joint corpus must union
those links, not treat this chapter's groups as unrelated to older chapters.
The exact `rowMatches2` regression example was not sent to the teacher or added.
These illustrations are not a new evaluation set.

## Files

- `records.json`: accepted tasks, parent/family/group links, parameter permutations,
  teacher provenance, source hashes, API use and reviewed JS reference source.
- `programs/*.vera`: teacher answers; no silent code repairs.
- `tests/*.json`: replayable input/expected values. Restore numeric `-0` when
  `negativeZero:true` before comparing; JSON itself loses the sign.
- `teacher/*-request.json`, `*-response.json`: exact prompts and response text,
  response IDs/model/usage; no credentials. The JSON envelope here is the teacher
  collection protocol, **not the local model's training or inference protocol**.
- `training-prefill.jsonl`: minimal `You write VERA functions.` system, natural
  task, fenced assistant function. `assistantPrefix` is the trusted `vera` fence,
  signature and opening brace. `completion` is body + closing brace + closing fence.
- `manifest.json`: counts, source/joint hashes, file hashes, policies.

The assistant answer contains no thinking tags. A continuation-aware trainer must
mask **all prompt and assistant-prefix tokens**, supervise only `completion`, and
append the tokenizer's EOS. Do **not** feed this file unchanged to the old
`train-lora.py`: that script does not yet implement the supplied assistant-prefix
loss boundary. The old adapter and all-chapter training snapshot are untouched.

## Verification and limits

```bash
export VERA_TYPESCRIPT_PATH=/path/to/typescript.js
node tools/vera-dataset/check-illustrative-stdlib.js
```

This recompiles every answer, reruns all cases, replays references and argument
swaps, checks old-holdout alpha isolation and source snapshots, and verifies the
prefill export and teacher hashes. It also verifies that `.includes` and reversed
containment mutants reject. No network access is needed for replay.

The references are reviewed authored JS implementations from the parent chapter,
not generated by the teacher from its candidate, but are not an external independent
specification. Finite tests do not prove equivalence. Numeric comparisons allow
1e-10 relative/absolute error for nonzero results, with signed zero exact.
Prompts received an assistant review; less formal wording can still be ambiguous.
For example, some length prompts say characters instead of explicitly saying code
points; these must not be interpreted as grapheme-cluster specifications. Domain
restrictions remain recorded in each record, even when a concise prompt omits
irrelevant upper bounds. Do not claim exhaustive prompt correctness.

The first batch covers 21 math/string API names lexically, not every runtime branch
or all stdlib APIs. There is no random/time/UI generation in this tier yet. Passing
these tests is not evidence the small local model has learned the APIs: no new
training or model evaluation has run on these examples.

## Generation/reproduction

```bash
ARKESTR_API_KEY=... node tools/vera-dataset/illustrative-stdlib.js NEW_DIR 40
```

The default endpoint/model can be explicitly overridden with
`VERA_CLOUD_ENDPOINT` / `VERA_CLOUD_MODEL`. Requires the existing local joint
manifest at `<external-joint-manifest>`.
Live teacher generation is nondeterministic. To reproduce accepted artifacts without
another teacher request, copy `teacher/` to a fresh output directory and rerun the
builder; cached request hashes are checked. Completed manifests refuse overwrite.
Keep fewer-than-three prompt-review acceptances; do not replace rejected answers
with hand fixes while claiming they came from the teacher.
